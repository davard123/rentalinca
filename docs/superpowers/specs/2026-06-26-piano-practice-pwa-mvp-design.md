# 钢琴麦克风陪练 PWA — 第 1 期 MVP 设计

- **日期**: 2026-06-26

- **参考竞品**: 小叶子钢琴-智能陪练（The ONE）

---

## 1. 背景与目标

做一个**自用**的钢琴陪练 App，灵感来自小叶子智能陪练。核心是：对着电钢弹琴，软件用麦克风听音，实时判断弹对/弹错、定位错音、给出提示。

**明确不要**的东西：付费/订阅、真人 1v1 陪练客服、商城等商业化内容。纯软件、纯自用、手机和 iPad 上能用即可。

本设计文档只覆盖**第 1 期 MVP**。整体项目分 4 期（见第 11 节），每期单独写 spec。

### MVP 的唯一目标

验证整个项目最大的技术风险：**纯麦克风能否可靠地听准你弹的单音**。

跑通这一条端到端链路即算成功：
> 导入一个 MIDI → 抽出单音旋律 → 瀑布流显示 → 对着电钢用麦克风弹 → 弹对变绿前进、弹错停住等你、显示小键盘提示。

## 2. 关键决策记录（含取舍理由）

| 决策 | 选择 | 理由 |
|---|---|---|
| 技术形态 | **网页 PWA**（非原生 iOS） | 用户主力开发环境是 Windows，做 web 最契合其技能；Safari 打开即用，无需上架/开发者账号/Mac；开发者可直接在 Windows 上写完并调试 |
| 延迟担忧 | **不是问题** | App 只做"听音分析"不发声，声音由电钢零延迟发出；且识谱模式自定节奏、不做实时节拍判定，几十毫秒的识别延迟无感。音高检测本身需要 ~40ms 采样窗口，原生与网页一致 |
| 输入方式 | **纯麦克风**（不接 MIDI 线） | 用户明确要求不接线、纯软件听音。已知 MIDI 连接更准更易，但用户选择麦克风 |
| 复音范围 | **仅单音**（单手旋律/一次一个音） | 纯麦克风做实时复音识别是研究级难题，DIY 不可靠。单音用自相关算法可做得可靠、低延迟 |
| 曲谱来源 | **导入 MIDI 文件** | 网上免费 MIDI 多；MIDI 含精确音符+时间；遇和弦取最高音作主旋律 |
| 显示形态 | 第 1 期先做**瀑布流**；五线谱留到第 3 期 | 瀑布流用裸 MIDI 数据直接可画，实现快；五线谱需制谱引擎，工作量大 |
| 练习模式 | 第 1 期只做**识谱模式**（等你弹对才走） | 自定节奏、对延迟不敏感，最能隔离验证"听音可靠性"这个风险 |
| 八度容错 | **默认开启**（同音名不同八度算对） | 麦克风受泛音影响常把音听成高/低八度，不容错会频繁误停、打击练琴。需严格八度可后续加开关 |

## 3. 范围

### 包含（In Scope）
- 麦克风实时单音音高识别（噪音门 + 稳定去抖 + 起音检测）
- 导入单个 `.mid` 文件，抽取单音旋律线
- 瀑布流（钢琴卷帘）可视化
- 识谱模式状态机：弹对变绿前进、弹错/未弹则停住等待
- 小键盘提示：高亮当前目标音对应的琴键
- PWA 外壳：manifest + Service Worker，可"添加到主屏幕"、离线可用
- 八度容错匹配（默认开）

### 不包含（Out of Scope，留待后续期）
- 多维打分、评测模式（第 2 期）
- 五线谱显示（第 3 期）
- 提升模式（难点循环）、节拍器/调速、曲库管理（第 4 期）
- 复音/和弦/双手同时识别
- 付费、账号、云同步、真人陪练、商城

## 4. 架构与模块

5 个职责单一、可独立理解和测试的模块。

### 4.1 PitchEngine（音高引擎）
- **职责**：把麦克风输入转成"当前稳定音 = 哪个 MIDI 音号"的事件流。
- **实现**：`getUserMedia` → `AudioContext` → `AudioWorkletNode` 内跑自相关（autocorrelation）音高检测 → 通过 `port.postMessage` 把频率/置信度发回主线程 → 主线程换算为 MIDI 音号。
- **内部处理**：
  1. **噪音门**：输入音量（RMS）低于阈值时忽略，不产生音。
  2. **稳定去抖**：一个音高需持续 N 毫秒（如 ~50ms）才确认，防跳动。
  3. **起音检测**：检测重新触键（音量上升沿 / 音之间的间隙），保证连续两个相同音不会被自动跳过。
- **接口**：
  - 输入：无（麦克风）；`start()` / `stop()`。
  - 输出：事件 `onNoteOnset({ midiNote: number, frequency: number, confidence: number })`；以及 `onPitch(midiNote | null)` 当前音流。
- **依赖**：浏览器麦克风权限、Web Audio API、AudioWorklet。

### 4.2 MidiImporter / ScoreModel（曲谱）
- **职责**：解析 `.mid`，抽出单音旋律线。
- **实现**：用 `@tonejs/midi` 解析；对每个时间点若有多个同时音，取**最高音**作为主旋律；合并为有序音符序列。
- **接口**：
  - 输入：MIDI 文件（`ArrayBuffer`）。
  - 输出：`Score = { tempo, notes: NoteEvent[] }`，其中 `NoteEvent = { midiNote, startBeat, durationBeats }`。
- **错误**：解析失败或找不到任何音符 → 抛出可读错误。

### 4.3 PracticeEngine（识谱模式状态机）— 核心
- **职责**：识谱模式的比对逻辑。纯函数式/可单测，不碰音频和 DOM。
- **状态**：`score`、`currentIndex`、每个音的状态（pending / current / done）。
- **逻辑**：收到 PitchEngine 的 note onset：
  - 与 `score[currentIndex].midiNote` 比对（八度容错：比较 `midiNote % 12`，默认开）。
  - 匹配 → 当前音标记 done（变绿）、`currentIndex++`。
  - 不匹配 → 状态不变（停住等待），可标记"刚才弹错了"以触发小键盘提示。
- **接口**：
  - `loadScore(score)`、`onDetectedNote(midiNote) -> StateUpdate`、`reset()`。
  - 暴露 `currentTargetNote`、`completedCount`、`isFinished`、`lastWasWrong`。

### 4.4 FallingNotesRenderer（瀑布流 UI）
- **职责**：Canvas 绘制音符条带。识谱模式下不按时钟下落，而是"弹对后整条向前推进"。
- **绘制**：纵轴=音高，横向条带=音符；当前目标音停在判定线并高亮；已完成=绿色；其余=待弹色。
- **接口**：`render(scoreState)`，由 PracticeEngine 状态驱动。

### 4.5 MiniKeyboard + App 外壳
- **MiniKeyboard**：画一排钢琴键，高亮当前目标音对应的键（弹错或卡住时强调）。
- **App 外壳**：`<input type="file" accept=".mid,.midi">` 导入曲目；开始/停止按钮；进度显示；PWA manifest + Service Worker。

---

## 5. 数据流

```
麦克风
  → PitchEngine (getUserMedia → AudioWorklet 自相关 → 频率)
  → 主线程换算 MIDI 音号 + 噪音门/去抖/起音
  → PracticeEngine.onDetectedNote(目标比对)
  → 状态更新
  → FallingNotesRenderer + MiniKeyboard 重绘

导入时: MIDI 文件 → MidiImporter → Score → PracticeEngine.loadScore()
```

## 6. 错误处理

| 情况 | 处理 |
|---|---|
| 麦克风权限被拒 | 友好提示 + 开启指引；不崩溃 |
| 非 HTTPS 环境（iOS 不给麦克风） | 检测到无法获取麦克风时提示需 HTTPS / localhost |
| MIDI 解析失败 / 无旋律 | 可读错误提示，允许重新选文件 |
| 环境噪音误触发 | 噪音门 + 置信度阈值 + 稳定去抖三重过滤 |
| 八度识别偏差 | 默认八度容错匹配 |
| 同时按多键（破坏单音假设） | 引擎只认主音，可能误判 —— MVP 明确只练单音 |

## 7. 测试策略

- **单元测试（Node + vitest）**，覆盖纯逻辑：
  - `MidiImporter`：已知 `.mid` → 预期 `Score`（含和弦取最高音的用例）。
  - `PracticeEngine`：喂入"对 / 错 / 重复音 / 八度偏移"序列，断言前进与停住行为。
  - 频率 → MIDI 音号换算。
  - 噪音门阈值逻辑。
- **音频 I/O**：无法自动化，人工测（见验收标准）。

---

## 8. 验收标准（MVP 成功判据）

对着电钢**慢速弹 C 大调音阶**（C4→C5）：
- App 正确跟随，**≥95% 不误停、不漏判**。
- 故意弹错音时，App 能**停住**并在小键盘上**高亮正确的目标键**。
- 弹对错音后再弹对，能正常继续前进。

达到即证明纯麦克风听音路线可行，可进入第 2 期。

## 9. 部署须知

- **iOS Safari 要求 HTTPS 才授予麦克风权限**。
- 本机开发：`localhost` 豁免 HTTPS，直接可调。
- 装到 iPhone/iPad 使用：托管到免费 HTTPS 静态站（GitHub Pages / Cloudflare Pages / Netlify 任一），再"添加到主屏幕"。

## 10. 技术风险与缓解

| 风险 | 缓解 |
|---|---|
| 麦克风单音识别在电钢上的可靠性（延音、泛音、八度误判） | 这正是 MVP 要验证的；用噪音门/去抖/起音/八度容错降低误判；验收标准量化 |
| AudioWorklet 在 iOS Safari 的兼容性 | 早期在目标设备上实测；必要时回退 ScriptProcessor/AnalyserNode |
| 自相关对低音/弱音不稳 | 单音阶验收先覆盖中音区；窗口大小调参 |
